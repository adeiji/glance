# Glance rules

Glance is a web page beside Claude Code that shows each answer as a picture and reads it aloud. These rules reach every session through the Glance plugin's session-start hook, and the Glance server adds them to the sessions it starts itself, so nothing in CLAUDE.md is needed. The exact paths for this machine are appended at the end.

## HTML-first answers

Favor HTML over text. Any answer beyond a quick one-liner (an explanation, plan, review, comparison, status, what changed, how something works) goes onto the shared Glance board, shown visually with as little text as possible.

Visual means pictures. Draw them with the board's block languages, which the page renders: `<pre class="viz">` for cards, bars, steps, compare, facts and callouts, and `<pre class="mermaid">` for flows, sequences and timelines. The syntax and the section template are in `VIZ.md` next to these rules (path given at the end); read it before writing your first section. In Mermaid flowcharts, quote any label containing punctuation (`E["/board starts"]`), since bare `/ ( ) | { } :` are read as shape syntax and break the diagram. Hand-drawn SVG is only for mockups and illustrations those blocks can't express. Tables and bullet lists are still just text, so don't lean on them. Use words for labels and the few things a picture can't say. How long the text reply should be is set by the Terminal reply line at the end.

## Posting a section

Each session owns one `<section>` on the board, and posts it by writing one small file:
- Write your whole section to `<sections folder>/<your session id>.html` with the Write tool, overwriting it each time; the folder's path is given at the end. The Glance server folds that file into the board, replaces your previous section, and drops sections older than 24 hours. Never read or edit the board file itself, and never touch another session's file.
- The section is `<section id="session-<first 8 chars of session ID>" data-session="<full session ID>" data-cwd="<working directory>" data-updated="<ISO time>">`. When Glance started the session, the system prompt gives the exact tag and file name. In a terminal session the session ID is the folder name just above `scratchpad` in your scratchpad path; if there isn't one, make up a random UUID once and stick with it. `data-session` and `data-cwd` let the user reply to that session from the board, so always include them. Show the project folder, the session ID, and the time at the top so sessions are easy to tell apart.
- Every section includes a spoken narration as `<p data-say hidden>…</p>`: a few conversational sentences that talk the user through the visual, as if you were pointing at it ("on the left is…, the green check means…"). The board reads it aloud when the section changes, so the user can look at the picture instead of reading. Write it for the ear, but put any file name, path, command, or exact identifier in backticks: the board shows the narration as captions with those names exact, while the voice just says the name.
- In voice mode (the board's mic button), you're just talking: answer out loud in a few short sentences and only draw on the board when the user asks to see something.
- Keep a section to what's current. Replace it each time; don't let it pile up history. The board server archives every version per conversation, so earlier visuals stay viewable. When you're only tweaking the visual you already posted, add `<p data-say-update hidden>Updated the visual to …</p>` with one line on what changed; the board updates it in place and reads that line instead of the whole narration again.
- The user views it on the Glance page (address given at the end), served by `server.js` next to these rules, which also lets them chat with sessions from the page, and it updates live. If it doesn't seem to be running, run `node <path to server.js> --open`: it starts the server in the background only if needed and opens the page.
